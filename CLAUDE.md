# Notes for future sessions

- **Branch: work and push on `main` only** (user's instruction).
- **No engine work from this repo.** ModdableCaptureCardProvider is read-only
  reference here; if something needs an engine change, say so and stop.
- The repo root IS the addon folder: users clone it into MCCP's `addons/`.
  Engine + modding wiki live in DasMaffin/ModdableCaptureCardProvider
  (`docs/wiki/*.html`); its `addons_backup/pkmn_stats` is the FireRed mod the
  reader's design came from.
- Only pixels exist (capture card). Frames are NV12; we read the Y plane with
  `frame:region`, recognise on a worker, decide in Think. Geometry is measured
  at 1920x1080 (`SWSH.BOX` in `lua/autorun/10_mod.lua`, mirrored in
  `dev/gen_atlas.py`).
- Text styles: atlas entries carry `s` = "d" (dialogue box, dark on white)
  or "n" (speaker name plate, `SWSH.NAME`, white on dark, matched as a whole
  game-text entry when teaching). Only same-style glyphs compete.
- Fingerprints are measured from the line's BASELINE (median glyph bottom),
  not the band edge, so 1-3 px offsets don't matter; the atlas keeps up to 8
  DISTINCT variants per char (near-duplicates < 1.0 skipped) because a
  letter renders differently depending on its sub-pixel position.
- The font is not available to us (commercial, no romfs dump; the user won't
  dump their Switch). The atlas (`lua/autorun/05_atlas.lua`) is built from
  real captures only.

## DEV-ONLY glyph teaching -- DELETE FOR THE SHIPPING BUILD

Shipping = delete `lua/autorun/90_dev_teach.lua` and the whole `dev/` folder.
Nothing else depends on them (the reader only exposes the `SwSh.Result` /
`SwSh.Think` hooks and `SWSH.extraGlyphs`, which is nil without the dev file).

How it works:
- The reader marks unknown glyphs `[?]` (`\1` in `raw`) and returns their
  fingerprints.
- `90_dev_teach.lua` posts stable lines with unknowns to the teacher worker
  `dev/teach/teach_<lang>.lua` (= game text from CPokemon/swsh-text +
  `dev/teach/teacher.lua`, generated by `dev/gen_teach.py`). If exactly one
  reading fits the game text, the letters are learned, saved to
  `data/<MOD_NAME>/learned.txt`, logged ("DEV learned new letter ..."), and
  used at once. There is also a manual "teach" panel in the overlay.
- **Baking**: the user sends their `learned.txt`; copy it to
  `dev/learned/<something>.txt` and run `python3 dev/gen_atlas.py --check`.
  That writes the glyphs into `05_atlas.lua`, so no other user has to
  re-learn them. Do this whenever the user provides a learned.txt.
- Only `teach_en.lua` is generated so far; other languages:
  `python3 dev/gen_teach.py <swsh-text checkout> de fr ...`.

Log through `SWSH.log(level, ...)` (10_mod.lua): our own levels
(`SWSH.LV.dialogue`, "Teaching" in the dev file), colours from `SWSH.C`,
`SWSH.marked()` paints `[?]` red; it falls back to one plain string on
engines without LOG_LEVEL. `SIM_RICH=1 dev/sim.py ...` exercises the rich path.
Keep README.md's "Log messages" table in sync whenever a log line is added
or changed.

Dev tooling: `pip install lupa pillow numpy`; `dev/sim.py <1080p screenshot>`
runs the whole addon under a mocked engine (`SIM_DROP=xyz` hides atlas glyphs
to exercise teaching).
